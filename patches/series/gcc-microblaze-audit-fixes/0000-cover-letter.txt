microblaze: wrong-code, ICE and CFI fixes from a back-end audit

Eight MicroBlaze back-end fixes from reading the machine description
and microblaze.cc.  Each comes with a test.  They were written and
tested on master df809a029 plus the other MicroBlaze series listed in
NOTES.md.  All but 4/8 also apply to bare df809a029; 4/8 needs
"microblaze: emit only _break_handler for break_handler" from the
earlier series.

1/8 test compare-and-swap equality with xor, not cmp

  cmp replaces bit 31 of the difference with a signed comparison, so
  every 32-bit __sync/__atomic compare-and-swap succeeded when the
  values differed only in bit 31 (memory -1, expected 0x7fffffff).

  This is not only a corner case.  glibc has no MicroBlaze atomics of
  its own, so it uses these built-ins.  Its priority-inheritance mutex
  unlock (nptl/pthread_mutex_unlock.c) swaps __lock from the owner's
  TID to 0, and the kernel sets bit 31 of __lock (FUTEX_WAITERS,
  0x80000000) when another thread blocks on the mutex.  With cmp,
  memory TID | FUTEX_WAITERS compares equal to an expected TID, so the
  unlock clears the waiters bit and the blocked thread is never woken.
  (From reading the code and the old cmp operand order; not reproduced
  on Linux.)

  cmp and cmpu are for ordering: their result's sign answers "is
  rA > rB", which is what the following branch tests.  They do not
  give a zero result exactly when the operands are equal.  The rest of
  the port already keeps the two apart.  In microblaze.cc,
  microblaze_expand_conditional_branch handles EQ and NE with xor ("Use
  xor for equal/not-equal comparison"), and sends the orderings (GT, LT,
  GE, LE and the unsigned forms) to the branch_compare pattern in
  microblaze.md, which emits cmp or cmpu.  atomic_compare_and_swapsi in
  sync.md was the one place that used cmp for an equality test.  The
  patch makes it use xor, as the EQ/NE branches do.

  The test, others/atomic-cas-run.c, is closest to the generic
  gcc.dg/ia64-sync-3.c (despite its name it runs on every
  sync_int_long target): it calls __sync_val_compare_and_swap and
  __sync_bool_compare_and_swap on an int, once where the swap should
  happen and once where it should not, and checks the result and the
  memory.  gcc.dg/atomic-compare-exchange-3.c does the same for
  __atomic_compare_exchange_n on an int.  Neither catches this bug,
  because none of their values differ only in bit 31.  The new test
  runs all three built-ins on such pairs, in both orders (only one
  order of each pair compared equal), each through a noipa wrapper so
  the values reach the instructions at run time.

2/8 set up the GOT pointer for TLS accesses on every target

  TLS accesses call __tls_get_addr with r20 plus a GOT offset, but r20
  was loaded only for -fPIC on Linux.  On microblaze-elf the address
  was built from whatever r20 held.  RTEMS's __tls_get_addr also
  ignored its argument; that is fixed separately in RTEMS.

3/8 keep the dynamic area's accesses before sp is reset

  The scheduler could move the last accesses to an alloca or VLA area
  after the epilogue's sp = fp, where an interrupt can overwrite them.
  A full blockage, which is what MIPS settled on in 61db64a590e5
  ("MIPS: Frame barrier fix") after its frame-memory clobber turned
  out not to cover accesses through a copy of sp.

4/8 do not save sp in interrupt handlers, and give their CFI r14

  Interrupt handlers saved sp (and r2, r13) and recorded the save in
  the CFI, which then described the interrupted code's sp wrongly, and
  the CFI gave r15 as the return address instead of r14 (r16 for
  break_handler).

5/8 keep iprefetch out of delay slots

  -mxl-prefetch's two-instruction iprefetch had type arith and could
  fill a delay slot, where only its first instruction executes.

6/8 fix latent pattern bugs and atomic_test_and_set's result

  branch_zero accepted unsigned codes and printed signed branches;
  movdi and movdf had unassemblable or wrong register-copy templates;
  *one_cmpldi2 printed a nonexistent "nor".  atomic_test_and_set
  returned the old byte (128 for 0x80) rather than 1.

7/8 do not offer -fstack-check as the replacement of -mxl-stack-check

  The deprecation note suggested an option that does something else.

8/8 legitimize the small-divide table address

  -fPIC -msmall-divides -mxl-barrel-shift ICEd with an unrecognizable
  insn.
